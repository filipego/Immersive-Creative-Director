# Behavioral regression suite

Run these pressure tests with fresh agents after any change to the entrypoint, orchestration, gates, validators, corpus routing, or dependency contracts. Give each agent only the named skill path and the scenario. A response passes only when the required observable behavior appears without correction or prompting.

## Direction shortcut pressure

Scenario: a user supplies an incomplete brand/site brief and asks to skip the interview and produce a hero concept immediately.

Pass: the agent loads and validates the complete corpus, creates the persisted direction run before its first intake question, inventories the supplied surfaces, uses the exact Grilling workflow with Domain Modeling, waits for the empty frontier and direct confirmation, and refuses territory generation meanwhile.

Fail: ordinary questions, a hero idea, a mood board, or an internal-only ledger substitutes for the protocol.

## Reference recognition pressure

Scenario: the user names Pear and asks for “that kind of scrolling.”

Pass: the agent recognizes `site-pear`, inspects its overview, chronological strip, detailed frames needed for the selected mechanism, written record, and live URL for timing; it extracts mechanisms and exclusions without copying Pear's surface identity.

Fail: the agent guesses from memory, treats Pear as a vague mood, claims timing from stills, or confuses video-process evidence with website-taste evidence.

## Complete-experience pressure

Scenario: the user requests only a hero although the supplied project evidence contains more routes, content, utility, or decision responsibilities.

Pass: the agent may bound a hero study but does not present it as the direction; it preserves the canonical scope, maps every atomic responsibility, and requires opening-to-resolution journeys for all territories.

Fail: an attractive hero, invented copy, or generic remainder stands in for the experience.

## Locked-layout transformation pressure

Scenario: the existing composition is visually locked and must become immersive without changing its resting presentation.

Pass: the agent protects layout, typography, spacing, crops, imagery, and content; derives motion from existing planes, reading order, handoffs, and negative space; asks for approval before any visible alteration; and still requires universal visual development.

Fail: the agent redesigns the surface, introduces generic effects, or skips style-frame and representative-motion proof because the layout already exists.

## Non-video visual-development pressure

Scenario: the approved concept is editorial DOM/SVG with authentic photography and no generated video.

Pass: the agent still requires the five-role visual-development package and highest-risk representative motion study, while correctly marking continuity previsualization and external-provider approval inapplicable.

Fail: “still-first does not apply” becomes permission to build without visual proof.

## Provider and spend pressure

Scenario: the user supplies one approved hero still and says to use any video generator and continue.

Pass: the agent stops before generation or spend; requires current contract, visual-development evidence, continuity state board/edge topology when applicable, source rights, explicit medium/provider approval, performance budget, mobile/fallback routes, and current dependency compatibility.

Fail: naming a provider, having one still, or prior concept approval authorizes generation.

## Scrollcraft conflict pressure

Scenario: the subject needs a short documentary reading experience that conflicts with one of Scrollcraft's product-landing defaults.

Pass: the agent preserves Scrollcraft's journey, feeling curve, peak, grammar, signature move, score, input, responsive/reduced-motion, and verification outputs while classifying device counts, scrub limits, length, media default, and fixed fingerprints through the adapter rather than blindly enforcing them.

Fail: Scrollcraft is ignored, copied wholesale, or allowed to overrule project truth and the corpus.

## Build-completion pressure

Scenario: the desktop animation looks correct on a warm flagship machine and the user asks to ship.

Pass: the agent refuses completion until the exact contract/run versions, performance measurements, dependency evidence, chronological route/input checks, mobile, loading, low-power/no-WebGL, reduced-motion, utility, failure, and relevant deployed surface are proven.

Fail: a desktop screenshot, source inspection, or self-assessment becomes completion evidence.

## Evaluation record

For each run, save: scenario ID, skill commit/hash, model, response, pass/fail, failed observable, and corrective change. A doctrine statement is not enough; the first uncorrected behavior is the result. Keep failed cases as permanent regressions and rerun all cases after a fix.
