# Preferences

These are Filipe’s active decision lenses, not universal design doctrine. Apply a record only when it helps the current subject and brief. Authority levels: **hard operating rule** applies unless Filipe explicitly changes it; **strong taste default** guides relevant choices without forcing a mechanism; **project direction** can narrow or suspend a default; an **evidence hypothesis** remains a question until corroborated.

## Active records

### `PREF-alive-authored-experience` — strong taste default

Make the complete visitor passage—layout, imagery, motion, pacing, utility, and resolution—feel intentionally authored. Do not mistake “alive” for constant movement, density, or spectacle.

### `PREF-simple-uncrowded-craft` — strong taste default

Favor clear hierarchy, strong focus, useful silence, and paced density so each important fact can register. This is not generic minimalism, empty space, or timid scale.

### `PREF-spatial-image-flow` — strong taste default

When imagery can carry space, give crop, scale, and distance shifts a distinct story or proof job: distant, editorial, near, environmental, or exit. Otherwise choose another mechanism; do not repeat zoom/parallax by habit.

### `PREF-scroll-agency` — strong taste default

Authored scroll can be powerful when input remains legible: bounded holds, honest-enough progress, orientation, one meaningful transformation per pin, and clean release. Reject a weak coercive contract, not scroll authorship categorically; strong contradictory evidence may qualify this condition.

### `PREF-causal-continuity` — strong taste default

Favor scenes whose transitions advance state, meaning, proof, or decision, including purposeful camera relationships and object transformation. Do not force literal plot or object-state chains on editorial, portfolio, or utility work better served by spatial or ceremonial continuity.

### `PREF-earned-takeover-and-release` — strong taste default

An editorial layout may earn a full environmental/media peak through restraint, authentic material, a held moment, and intentional return to comprehension or action. Do not make every image fullscreen or darken imagery merely to enlarge copy.

### `PREF-structural-particles-paths-and-play` — strong taste default

Use particles only with field topology or destination, paths only with milestones and legible geometry, and play only with a stable utility frame and limited toy box. Preserve the desired quality through another mechanism when these jobs are absent.

### `PREF-reject-generic-motion` — hard creative rule

Reject text reveals as the main idea, arbitrary parallax, floating-card choreography, shaking/pulsing emphasis, decorative particles, feature-led GSAP effects, and copied reference surfaces when they lack a concept-specific job. Rehabilitate familiar techniques only by giving them a real function; do not replace them with a rigid house formula.

### `PREF-codex-no-code-workflow` — hard operating rule

Codex desktop and OpenAI models own planning, implementation coordination, asset work, and verification when authorized. Give Filipe decisions, outcomes, and true dependencies—not tutorials or routine coding assembly.

### `PREF-in-app-browser` — hard operating rule

Use the active Codex desktop in-app Browser for reference study, browser comments, rendered critique, and verification. Resolve the compatible controller and inspect chronology/routes; do not use Chrome for convenience or make motion claims from code/screenshots alone.

### `PREF-concept-convergence` — hard operating rule for ordinary direction

Create three structurally distinct territories internally, reject the weakest, present the strongest two, and recommend one. Distinguish them by subject interpretation or coherence source, not surface variation. A narrower explicit request may change the count without weakening the quality bar.

### `PREF-media-posture` — hard tool-choice rule plus strong medium default

Use Codex/OpenAI directly where appropriate. Choose media by narrative job, value, continuity risk, control, cost, tool, scope, and fallback. Prefer authentic assets, generated stills, layers, sequences, or short clips when they provide better control; use continuous video only when temporal motion is necessary. Do not assume an external vendor, a budget limit, or a paid generator.

### `PREF-approval-boundaries` — hard operating rule

Concept approval precedes continuity-dependent production; approve continuity-critical sources before dependent motion; separately discuss/approve costly video, complex 3D, or external media; preserve visual locks; require explicit external-release authority. Continue reversible research, storyboards, and feasibility; ask only the next meaningful decision. Never turn concept approval into blanket spend, redesign, publication, contact, or submission authority.

### `PREF-adaptive-role` — hard operating rule

Identify direction, transformation, production, critique, or evolution, then continue through the authorized boundary. Do not implement in critique/research/direction mode, and do not stop at a plan when local build work is explicitly authorized.

### `PREF-skill-orchestration` — hard operating rule

Dynamically discover and fully invoke only relevant specialists under one Immersive synthesis. Design Loop nests Impeccable in visual build phases; Filipe Flow owns substantial execution dispatch; grilling plus domain modeling is the automatic reachable grill-with-docs equivalent; Watch owns supplied-video study. Poteto is limited to an approved distinct general code/product-behavior or final skill-authoring phase. Do not list names instead of running workflows, duplicate nested owners, use Poteto to wrap Design Loop/Scrollcraft, or let implementation select the premise or widen authority.

### `PREF-selective-evolution` — hard operating rule

Treat the library as selectively open: fully inspect a source, separate preference signal from novelty and conflict, choose add/merge/counterexample/reject, patch one canonical owner only with explicit installed-mutation authority, then run targeted regression. Prestige, a link, or visual novelty alone never earns admission.

## Resolve conflicts at runtime

Current explicit project direction controls that project. Hard rules stay active unless Filipe changes them. Strong defaults guide a relevant choice but yield to subject truth or a project decision. Evidence hypotheses must not be silently promoted. If a material conflict remains, state it once with a recommendation; do not “correct” the project back to this library.

Before presenting direction, privately identify relevant hard rules/defaults, project overrides, considered-and-rejected favored mechanisms, and any material conflict. Make the result belong to the subject, not a recognizable house style. New direct feedback can add, qualify, strengthen, suspend, or supersede a record only through an Immersive Discovery transaction; a single project reaction is not a global mandate.
