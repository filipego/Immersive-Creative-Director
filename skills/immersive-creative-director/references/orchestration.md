# Orchestration

Immersive Creative Director is the synthesis owner: protected kernel, approved concept, visual lock, authorization state, and final recommendation. Specialists cannot independently redefine the experience.

## Route deliberately

At intake, identify the mode—direction, transformation, production, critique, or evolution—and inspect actual inputs. Dynamically discover installed skills; do not assume a name, version, location, or wrapper remains available. Select only capabilities that change a decision. Before relying on one, invoke the **full skill**: read and follow its complete `SKILL.md`, load required supporting resources, perform its real workflow, and integrate the result. Naming a capability or borrowing its vocabulary is not invocation.

Record each capability as `selected`, `fully invoked`, `deferred` with the missing predicate/input, or `runner-reported`; also record its owner and decision. Only direct evidence that its complete workflow ran supports `fully invoked` or a skill-orchestration pass. If one is missing, say so, use the closest safe capability, and neither invent instructions nor install it. Specialist approvals remain in force; no playbook broadens authority.

Use the active Codex desktop in-app Browser for live sites, rendered critique, and web verification. Resolve the controller suitable for the active runtime. Do not use Chrome or infer an experience from code or screenshots alone.

## Capability routes and ownership

- `impeccable` provides substantive visual judgment and anti-generic critique in direction, transformation, production, and critique; use it in evolution when judging why a source works. For assumption-marked direction with no target or inspectable artifact, run its context and relevant judgment playbook, record a missing visual-authority or product-record limitation once, and leave any required persisted new-world interview deferred; Immersive remains the concept owner and must not claim the blocked persistence workflow completed. When `design-loop` owns a rendered phase, its Impeccable pass is nested and complete: do not independently load, invoke, or report Impeccable as a second workflow. A separate Impeccable pass is allowed only for a distinct non-rendered phase with its own predicate.
- `design-dna` separates transferable mechanism/system logic from recognizable reference identity. Use it for references, brand systems, or locked layouts; do not copy their surface.
- `grilling` with `domain-modeling` pressure-tests a consequential unresolved frontier and maintains terms/decisions. This is the automatic equivalent of the user-only `grill-with-docs` wrapper. If Filipe explicitly invoked that wrapper, use it rather than duplicating the session. Ask only the meaningful frontier; do not turn intake into an interview.
- `watch` is mandatory whenever a supplied video informs judgment. Complete its visual chronology with timestamps; exclude sponsor/commercial material and resume afterward. Verify relevant companion evidence and translate external-agent/tool demonstrations into Codex/OpenAI workflow without hardwiring a vendor.
- `scrollcraft` owns approved, genuinely scroll-driven scene implementation: score, input mapping, orientation, hold/release, responsive behavior, and fallback. It is not a default effect engine.
- `design-loop` owns a reference-led rendered build/critic phase and its nested Impeccable pass. Use only after build/refinement authorization on a target that can render and be freshly captured.
- `filipe-flow` is the sole outer dispatcher for a substantial multi-stage build, transformation, or audit/fix session; it receives the approved specification and selects the smallest execution set.
- `poteto-mode` is conditional: use it only for an approved, distinct general application/behavior or final skill-authoring phase not owned by Design Loop or Scrollcraft. In substantial work Filipe Flow remains outer dispatcher; in a small focused general-code phase, use Poteto directly. Never use it for research, direction, critique, evolution analysis, or merely because code exists.
- `imagegen` may make approved, constrained stills/layers/plates/storyboards. Concept approval does not imply continuity-dependent production or costly video/3D.
- Route GSAP, framework, and performance specialists only when their technology predicates match the approved mechanism. They answer how, not what.
- Use `browser-proof` alone when the claimed final surface is the rendered website in the browser. Add `actual-surface-verifier` only when the completion claim concerns a distinct deployed, exported, native, installed, or otherwise separate final surface. Never select both for the same browser surface, even as a future plan.

Nested ownership is one chain, not parallel reports: Immersive specification → Filipe Flow dispatch → Design Loop → Impeccable. Poteto may join only as a separate bounded general phase. Immersive retains acceptance criteria and singular synthesis without duplicating execution.

## Mode recipes

**Direction.** Start with Immersive + Impeccable. Add Design DNA for a reference/brand system, Watch for video, and grilling/domain modeling only for consequential ambiguity or pre-approval stress testing. Load `production.md` as a feasibility advisor when the direction turns on medium value/cost, continuity assets, spatial travel, or a production tier; retain direction-only authority and do not invoke implementation owners. Reason about scroll in the concept, but defer Scrollcraft’s build workflow. Develop three distinct territories internally, reject one, present two, recommend one, and stop before continuity-dependent production.

**Transformation of a still/locked layout.** Start with Immersive + Impeccable + Design DNA; inspect the live surface in the in-app Browser when available. Derive behavior from crop, planes, reading order, handoffs, and negative space while preserving the visual lock. Do not use Design Loop, Scrollcraft, or Filipe Flow until the direction is approved and implementation is requested.

**Production.** Freeze the approved specification: kernel, modes, mechanisms, visual lock, assets, responsive/fallback, and acceptance evidence. For substantial work hand it once to Filipe Flow; for a small phase use its focused owner. Design Loop handles render-led iteration; Scrollcraft approved scroll; Poteto only its distinct general phase. Respect gates for continuity sources, costly media, visible divergence, and external mutation.

**Critique.** Start with Immersive + Impeccable and inspect rendered work in the in-app Browser. Add grilling/domain modeling only if the premise needs pressure-testing. Diagnose preserve/repair/remove decisions with evidence; do not build or invoke Design Loop unless the request expands into iteration.

**Evolution.** Use Immersive Discovery in `evolving-the-library.md`: Immersive + Impeccable + in-app Browser for a site or Watch for a video. Add Design DNA and grilling/domain modeling only when mechanism identity or a doctrine conflict needs them. Do not load production specialists unless the production method itself is the lesson.

## Reconcile, then answer

Current project instructions and hard rules govern; then the approved kernel and visual lock; then relevant taste defaults and evidence. Compare conflicts against subject specificity, narrative job, page mode, agency, feasibility, and authority. Record the rejected branch internally. Deliver one strengthened concept or diagnosis, not a pile of specialist reports. State provenance only when it changes Filipe’s evaluation or a required capability was unavailable.
