# Orchestration

Immersive Creative Director is the synthesis owner: protected kernel, approved concept, visual lock, authorization state, and final recommendation. Specialists cannot independently redefine the experience.

## Route deliberately

At intake, identify the mode—direction, transformation, production, critique, or evolution—and inspect actual inputs. Dynamically discover installed skills; do not assume a name, version, location, or wrapper remains available. Select only capabilities that change a decision. Before relying on one, invoke the **full skill**: read and follow its complete `SKILL.md`, load required supporting resources, perform its real workflow through its own completion criterion, and integrate the result. Naming a capability, reading its entrypoint, borrowing its vocabulary, or asking a look-alike question is not invocation.

Record each capability as `required`, `running`, `complete`, `deferred` with the missing predicate/input, `blocked`, or `runner-reported`; also record its owner, current workflow step, direct evidence, and decision. `Complete` requires the capability's actual completion criterion—not file access or partial advice. If a required capability is missing, say so and stop at the dependent boundary; never silently substitute a generic workflow or claim completion. Specialist approvals remain in force; no playbook broadens authority.

Use the active Codex desktop in-app Browser for live sites, rendered critique, and web verification. Resolve the controller suitable for the active runtime. Do not use Chrome or infer an experience from code or screenshots alone.

## Mandatory corpus grounding

The complete installed corpus is required context on every invocation. Read the compact evidence index and the full reference ledger before intake questions, specialist routing, concept generation, critique, or production planning. Do not rely on memory from a previous turn, a one-line record, a user explanation of a source, or generic design training.

Complete this protocol:

1. Read every core file named in `SKILL.md` completely. Record each file as `complete` only at EOF.
2. Resolve every user-named reference against names, domains, URLs, video IDs, titles, and likely dictated variants. For example, “Pear,” “peer,” and `pear.no` resolve to `EVID-site-pear`; its companion process resolves to `EVID-video-reference-transfer` / `39IlNR-P3-Q`.
3. For each named reference, recover its actual chronology, composition, motion grammar, orientation system, peak/resolution, polish evidence, anti-pattern boundary, production implications, observed limits, and linked video/process lessons before discussing it. Search the complete corpus before asking the user to explain a source already present there.
4. Build an internal evidence lineage for the active work. Every Direction or Transformation territory must use at least two website records from different mechanism families, one educational/process record, one explicit non-transferable surface boundary, and one statement of why the synthesis belongs to the current subject. Critique and Production must use at least one relevant website record and one process record. Immersive Discovery must compare the supplied source against the complete existing corpus.
5. Carry the selected evidence into Grilling recommendations, territory generation, rejection, asset/production choices, and quality gates. The lineage is not decorative provenance: removing it must materially weaken or alter the judgment.

Corpus grounding is complete only when all core files are read, every named reference is correctly recognized, its detailed evidence can be recovered without invention, and the required evidence lineage is recorded. If any part fails, mark grounding `blocked` and do not ask design questions or generate creative output.

## Mandatory Grill-with-Docs intake

Every new Direction or Transformation engagement must complete the real Grill-with-Docs behavior before concept generation. The `grill-with-docs` wrapper is user-invoked, so automatic use means fully invoking both `grilling` and `domain-modeling`; it never means asking ordinary clarification questions in their place. If Filipe explicitly invoked the wrapper, follow it directly and do not duplicate the session.

Complete this protocol exactly:

1. Inspect available files, surfaces, routes, facts, prior decisions, and glossary material first. Facts are the agent's work; decisions are the user's.
2. Read and follow the complete `grilling` and `domain-modeling` skills and all resources they require. Announce that the mandatory intake is running.
3. Build the decision tree. Ask the entire current frontier in one round, including every question whose prerequisites are settled. Use the Grilling format exactly for every decision:

   ```text
   ❓ **Q1** - **<question title>**: <question and choices>

   ➡️ <recommended answer>
   ```

4. End the turn after the frontier questions and wait. Do not attach concepts, speculative directions, or an abbreviated answer.
5. After the user's answers, recompute the frontier and repeat the exact question format until no branch remains silently assumed.
6. Apply Domain Modeling during every round: challenge conflicting terms, sharpen fuzzy language, test concrete edge cases, check available project evidence, update the appropriate glossary when terms resolve, and offer an ADR only when its three required predicates hold.
7. When the frontier is empty, summarize the shared understanding and ask the user to confirm it. Concept work begins only after that confirmation.

The following are bypass attempts, not exemptions: “the brief is clear,” “the only missing item is a screenshot,” “there is no consequential ambiguity,” “I can infer this,” “I will ask one quick question,” or “the wrapper is unavailable.” When the wrapper is unavailable but both component skills exist, run both component workflows. If either component is unavailable, mark intake `blocked` and do not generate concepts.

When a canonical, user-confirmed discovery record already contains the answers and states that shared understanding is complete, ingest it as prior decision evidence. Run Grilling and Domain Modeling as an audit of the remaining frontier; do not ask settled questions again. A model-authored summary without user confirmation is evidence to inspect, not proof that decisions were made.

## Mandatory experience contract

After shared understanding and before territory generation, execute [experience-contract.md](experience-contract.md). This is agent legwork, not another interview: derive routes, copy, responsibilities, content items, states, and source locations from the inspected project evidence. Ask only when a missing user decision blocks a row.

Record the versioned canonical JSON, contract header, `CONTRACT-route-inventory`, `CONTRACT-copy-provenance`, `CONTRACT-responsibility-map`, and one complete `CONTRACT-state-storyboard` per territory. Keep any human-readable projection in the project artifact or internal record so the user-facing answer may remain compact. Compact presentation never reduces contract demand. Run the bundled validator before approval and build boundaries and attach its current `PASS`/`FAIL` evidence to the protocol ledger. Pass the same contract version to every specialist; any scope/content/copy/story drift returns through a `SCOPE-CHANGE-*` row and a validator rerun rather than being absorbed silently.

A focus request chooses the next fragment to explore; it does not amend the canonical scope. A focused artifact may become an approval candidate only when the user explicitly bounds the canonical deliverable to it. Otherwise label it non-approvable until the complete contract passes, and do not assign omitted content or route responsibilities to unspecified later work.

## Capability routes and ownership

- `impeccable` provides substantive visual judgment and anti-generic critique in direction, transformation, production, and critique; use it in evolution when judging why a source works. For assumption-marked direction with no target or inspectable artifact, run its context and relevant judgment playbook, record a missing visual-authority or product-record limitation once, and leave any required persisted new-world interview deferred; Immersive remains the concept owner and must not claim the blocked persistence workflow completed. When `design-loop` owns a rendered phase, its Impeccable pass is nested and complete: do not independently load, invoke, or report Impeccable as a second workflow. A separate Impeccable pass is allowed only for a distinct non-rendered phase with its own predicate.
- `design-dna` separates transferable mechanism/system logic from recognizable reference identity. Use it for references, brand systems, or locked layouts; do not copy their surface.
- `grilling` with `domain-modeling` owns the mandatory Direction/Transformation intake above. In Critique, Production, or Evolution, invoke it when a consequential unresolved frontier exists. This pair is the automatic equivalent of the user-only `grill-with-docs` wrapper and must run as the complete design-tree interview plus active glossary/decision discipline.
- `watch` is mandatory whenever a supplied video informs judgment. Complete its visual chronology with timestamps; exclude sponsor/commercial material and resume afterward. Verify relevant companion evidence and translate external-agent/tool demonstrations into Codex/OpenAI workflow without hardwiring a vendor.
- `scrollcraft` owns approved, genuinely scroll-driven scene implementation: score, input mapping, orientation, hold/release, responsive behavior, and fallback. It is not a default effect engine.
- `design-loop` owns a reference-led rendered build/critic phase and its nested Impeccable pass. Use only after build/refinement authorization on a target that can render and be freshly captured.
- `filipe-flow` is the sole outer dispatcher for a substantial multi-stage build, transformation, or audit/fix session; it receives the approved specification and selects the smallest execution set.
- `poteto-mode` is conditional: use it only for an approved, distinct general application/behavior or final skill-authoring phase not owned by Design Loop or Scrollcraft. In substantial work Filipe Flow remains outer dispatcher; in a small focused general-code phase, use Poteto directly. Never use it for research, direction, critique, evolution analysis, or merely because code exists.
- `imagegen` may make approved, constrained stills/layers/plates/storyboards. Concept approval does not imply continuity-dependent production or costly video/3D.
- Route GSAP, framework, and performance specialists only when their technology predicates match the approved mechanism. They answer how, not what.
- Use `browser-proof` alone when the claimed final surface is the rendered website in the browser. Add `actual-surface-verifier` only when the completion claim concerns a distinct deployed, exported, native, installed, or otherwise separate final surface. Never select both for the same browser surface, even as a future plan.

Nested ownership is one chain, not parallel reports: Immersive specification → Filipe Flow dispatch → Design Loop → Impeccable. Poteto may join only as a separate bounded general phase. Immersive retains acceptance criteria and singular synthesis without duplicating execution.

## Mode recipes

**Direction.** Start with the mandatory Grilling + Domain Modeling intake, then build the mandatory experience contract before territory generation, then Immersive + Impeccable. Add Design DNA for a reference/brand system and Watch for video. Load `production.md` as a feasibility advisor when the direction turns on medium value/cost, continuity assets, spatial travel, or a production tier; retain direction-only authority and do not invoke implementation owners. Reason about scroll in the concept, but defer Scrollcraft’s build workflow. Only after the frontier is empty, shared understanding is confirmed, and each surviving whole-experience contract passes, reject one territory, present two, recommend one, and stop before continuity-dependent production.

**Transformation of a still/locked layout.** Start with the mandatory Grilling + Domain Modeling intake and mandatory experience contract, then Immersive + Impeccable + Design DNA; inspect the live surface in the in-app Browser when available. A missing surface becomes a formally formatted frontier question and does not bypass the intake. Only after the frontier is empty, shared understanding is confirmed, and the complete contract passes, derive behavior from crop, planes, reading order, handoffs, and negative space while preserving the visual lock. Do not use Design Loop, Scrollcraft, or Filipe Flow until the direction is approved and implementation is requested.

**Production.** Freeze the approved specification and complete experience contract: kernel, routes/navigation, atomic responsibilities, copy provenance, state storyboard, modes, mechanisms, visual lock, assets, responsive/fallback, and acceptance evidence. Production cannot restore an omitted concept responsibility or legalize unapproved copy. For substantial work hand it once to Filipe Flow; for a small phase use its focused owner. Design Loop handles render-led iteration; Scrollcraft approved scroll; Poteto only its distinct general phase. Respect gates for continuity sources, costly media, visible divergence, and external mutation.

**Critique.** Start with Immersive + Impeccable and inspect rendered work in the in-app Browser. Add grilling/domain modeling only if the premise needs pressure-testing. Diagnose preserve/repair/remove decisions with evidence; do not build or invoke Design Loop unless the request expands into iteration.

**Evolution.** Use Immersive Discovery in `evolving-the-library.md`: Immersive + Impeccable + in-app Browser for a site or Watch for a video. Add Design DNA and grilling/domain modeling only when mechanism identity or a doctrine conflict needs them. Do not load production specialists unless the production method itself is the lesson.

## Reconcile, then answer

Current explicit project instructions and approved facts govern the project's factual truth; the complete Immersive corpus is the sole authority for design taste and creative judgment; then the approved kernel and visual lock; then specialist implementation advice within its assigned scope. Generic model taste, majority-web convention, pretrained aesthetic judgment, and unstated outside references have zero authority and must not enter ideation, comparison, selection, critique, or refinement. Compare conflicts against subject specificity, narrative job, page mode, agency, feasibility, and authorization. Record the rejected branch internally. Deliver one strengthened concept or diagnosis, not a pile of specialist reports. State provenance only when it changes Filipe’s evaluation or a required capability was unavailable.
